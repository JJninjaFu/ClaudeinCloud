# ClaudeinCloud notes for Claude

- JJ's playground for browser games. Each game lives in its own folder as a single `index.html` (no build step).
- Games use three.js **r128** loaded from `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js` so they also publish as claude.ai artifacts (the artifact CSP only allows cdnjs, jsdelivr, unpkg; fonts only from Google Fonts).
- Game HTML files are written as artifact bodies: they start with `<title>` and `<style>`, not `<!doctype>`/`<html>`. Keep `[hidden]{display:none!important}` in each file's own CSS.
- JJ plays on his phone a lot: every game needs touch controls (virtual sticks + big buttons) as well as keyboard and gamepad.
- Style family (shared with Road Crew): safety yellow `#f5b800`, survey orange `#ff6b1a`, dark asphalt panels, Big Shoulders Display / IBM Plex Sans Condensed / IBM Plex Mono.
- Show player-facing measurements in feet and inches (US).
- Testing: headless Chromium via Playwright with `--use-gl=swiftshader`. `window.__pool` (Pool Dig) and `window.__crane` (Topping Out) expose state and a `step(dt, input)` hook for scripted tests. When teleporting the crane in a test, zero `cr.prevV` and `cr.aT` or the load will swing wildly.
- Skyscraper Sim is the long-term plan (demo → dig → pour → steel on one lot); see README. Build each phase as its own playable game first.
- Never put one big ground plane under a dig grid: anything dug below it gets hidden. Build the surroundings as a ring of planes outside the grid (fixed in Pool Dig and Dig & Pour).
- Game files start with charset + viewport `<meta>` tags before `<title>` so they scale right on phones when served from GitHub Pages (harmless as artifact bodies). Root `index.html` is the Pages game menu (a full HTML doc); add new games to it.
- Mineral Fork (dirt bike hillclimb): `window.__game` exposes state; `__game.sim(seconds)` runs the autopilot headless (`autoFeather` true = smooth throttle, which should top out both days; false = pinned, which should fail on the scree).
- Mineral Fork multiplayer: PeerJS rooms (`mineralfork-v1-` + 4-char code), host relays 15 Hz snapshots, 4 riders max, no rider collisions. `__game.mp` exposes the state. To test without the internet, inject a BroadcastChannel stand-in for `window.Peer` before load and open several pages; software-rendered Chromium runs ~1 fps, so drive riders with `__game.sim()` and `bring_to_front()` the page you need frames from.
- Topping Out has three modes: gantry (default), tower (swinging load), hand (drag-to-place). `window.__dig` exposes Dig & Pour state (`startRebar()` skips to the pour).
- Funnin' N Gunnin' (`funnin-n-gunnin/`, RWR-style war): 160 x 120 m map, 1 m terrain grid (`H` vs original `H0`, craters/digging capped at `MAXDIG` below original), building walls are 1 m blocks on 2 levels (`blkIdx`, a wall falls if the block under it dies), bots path with BFS flow fields per point (`rebuildFlow`). 50 soldier slots (0-24 red, 25-49 blue); a human takes over a bot slot. `window.__war` exposes state; `__war.sim(seconds)` runs it headless, `__war.frame()` renders one frame. Multiplayer: PeerJS rooms (`funnin-v1-` + code), host runs all bots, clients own their soldier's position and send triggers; world changes are ops (`cr` crater, `dg` dig, `bd` blocks, `tf` tree) kept in `G.history` so mid-match joiners replay them. Same BroadcastChannel Peer stand-in test works (serve over http, not file://, so the channel is shared).
- Survivin' Skydivin' (`survivin-skydivin/`): solo jump. Plane flies the jump run into the wind over an ideal spot; canopy flight runs at up to 2x time (`timeScale()`), back to 1x below 160 ft. Malfunctions: `twist`, `streamer`, `pcintow`, `lineover` (canopy collisions also wrap you). `window.__sky` exposes state; `__sky.forceMalf = 'streamer'` forces the next opening, `__sky.fast = true` skips the results delay, `__sky.sim(seconds, {idle})` runs the autopilot headless (it flies the whole jump and should land standing up), `__sky.frame()` renders one frame.
- Skydivin' 2 (`skydivin2/`): 4-way formation skydiving. Its world (DZ, trees, hangar, power line, jumper/canopy models) is a copy of the Survivin' Skydivin' world block, so fix bugs in both. Formations are slot lists in `FORMS` ([right, forward, facing] in the formation frame). Host runs bots and the formation (center = average of jumpers, hold 3 s). Freefall positions go over the network relative to a deterministic reference body (`buildRef`/`refAt`) so latency doesn't wreck levels at 120 mph; switch to absolute after break off. PeerJS rooms `skydivin2-v1-` + code, 15 Hz. `window.__sky2.solo(seed)` starts a bot jump, `__sky2.auto = true` lets a bot fly your jumper, `__sky2.sim(seconds)`. The BroadcastChannel Peer stand-in test works (step every page in small 0.1 s chunks with short sleeps so messages flow).
- Test environment note: cdnjs may be blocked from the sandbox. Grab three.js r128 with `git clone --depth 1 --branch r128 --filter=blob:none --sparse https://github.com/mrdoob/three.js` + `git sparse-checkout set --no-cone /build/three.min.js`, then Playwright `page.route('**/three.min.js', ...)` to serve it.
- Funnin' N Gunnin' vehicles (v2): `vehicles[]` (per side jeep, APC, tank, jeep at `v.spot` by HQ), `VT` holds stats/seats (seat 0 driver, 1 gunner, rest riders; `sealed` = APC/tank hide and protect the crew). A soldier in a vehicle has `s.veh`/`s.seat` and is skipped by the foot AI. `vehStep(v, ctl, dt, auth)` drives (only `auth` crushes trees/sandbags/walls and runs people over), `botDrive` follows vehicle flow fields `vflow` (walls inflated by 2 cells), `botGunner` aims the turret, `crewUpdate` fills seats. Net: client drives its own vehicle and sends `V`/`TY`; snapshots carry `V` (vehicle states) and seat codes in soldier slot 10. `__war.vehicles`, `__war.respawnVehicle`, `__war.enterVehicle` help tests. Build parts live outside the repo; edit `funnin-n-gunnin/index.html` directly if they're gone.
- Rippin' N Flippin' (`rippin-n-flippin/`, stand-up jetski): water is three CPU FFT cascades (`Cascade`, 64², JONSWAP wind sea + swell scaled to Hs) uploaded as half-float textures, plus a shoaling surf swell (`surfAt`, table shared with GLSL) and a GPU ripple sim for the wake (`stepRipples`, window follows the ski). `waterAt(x,z)` is the physics-side sample of the same waves; `groundH` is the bay floor/beach in JS and GLSL. Hull physics: `HPTS` sample points with buoyancy + planing pressure along each point's normal, thrust vectoring at the pump (`SKI.nozzle`), air control torques when no point is wet. `window.__ski` exposes state; `__ski.sim(seconds, inputOrFn)`, `__ski.launch(vy)` throws the ski for flip tests, `__ski.freeCam = true` lets a test place the camera, `__ski.frame()` renders. Sun sits over the land so you ride into the glints. Handedness gotcha: the bow points +z, so the ski's local +x is the rider's LEFT, positive yaw about +y turns LEFT and positive roll about the bow axis leans RIGHT; all inputs use positive = right, so physics torques carry the minus signs. Steering is a yaw-rate controller (speed, gas and bank set the target rate), not raw nozzle torque. Ski and rider are built from primitives: lofted hull with flat-coloured livery strips (`hullHalfRing`, `hullStripColor`), two-bone IK for arms and legs (`twoBone`, `poseRider`), a canvas PMREM environment for reflections, and `SRGB()` because r128 has no colour management.
- Funnin' N Gunnin' trenches (v3): the order is op `tj` (job id, team, flat x,z list at 1.2 m spacing), each dig step is `tg` (job, node, step 1-5) which grades the 1 m height grid with `min()` toward a trench profile (`trenchGrade`, so peers that replay `G.history` get identical ground), `tl` lines a finished node with sandbags, `tc` closes the job. The lining is `liningH` (one flag per cell, deterministic, never computed from jittered positions) that `traceShot` and `losClear` read through `liningTopAt` as 0.5 m of cover (ignored within 2.4 m so you can shoot out); the bags are one InstancedMesh and `liningBlast` removes bags in craters. Bots: `s.job`/`s.nodeI`, `trenchWork` claims the first pending node, walks, crouches and digs; `trenchDrop` hands the node back when a fight starts; `trenchTick` (host, every 2 s) restaffs jobs; finished nodes go in `TR.spots`, which `findCover` prefers. Input: V, the TRENCH button or the pad Back button sets `TR.mode`, then a pointer drag (`groundPick`) or the pad cursor (`trenchPadUpdate`) feeds `trenchPush`, and release sends the order (clients send `{t:'tn', p}` to the host). Test hooks: `__war.trench.order(team, flat, issuerSlot)`, `__war.trench.TR`, and `__war.applyOp`/`__war.resetMatch` to replay history and compare `H`.
- Diggin' N Destructin' (`diggin-n-destructin/`, RTS): a copy of Funnin' N Gunnin's engine (1 m height grid `H`/`H0`, block walls, instanced soldiers, particles, synth sound) with an RTS layer. `H0` is the ground BEFORE the sand piles (so `H - H0 > 0.7` is loose dirt an excavator can fetch) and `levelPad` resets `H0` under a new building. Pieces: `UT` unit table + `WP` weapons (hitscan with a LOS gate `losOK`, rockets and shells as `projs`), BFS flow fields per destination cached by `navVer` (`getField`, `flowDir`; `markNav()` throttles rebuilds to once a second because terraforming and explosions change the ground constantly), vehicles refuse to enter cells steeper than 1.15 in `integrate` (that is what makes ditches and berms block them), structures `BT` placed with `placeOK`/`addBuilding`, one structure in production per team (`TS[team].build`, then place it) and a queue per building, power below demand halves speed, `up` upgrades from the Armory, harvester states seek/goto/load/return/unload. Terraforming (`terraform.js` part): `terraRemove`/`terraAdd` move conserved volume (net change over a dig/dump cycle is exactly 0), the excavator brain `updateExcavator` runs plan/goto/work/swing/dumpw with `findStand` (drivable ground within reach) and `findLoose` (heap to fetch from), engineers dig node by node (`orderDig`, `digRun`, `trenchGrade`, `trenchLine` sandbags, the same trench code as Funnin' N Gunnin'). The lining only blocks a ray near its target (`losClear`: `d > 2 && L - d < 3.4`) so soldiers aren't blinded by their own sandbags, and dug-in infantry (`u.dug`) stand up to look and fire. AI is `aiTick` (build order, trains, waves, defends). The file is assembled from parts that live outside the repo, so edit `diggin-n-destructin/index.html` directly. Test hook `window.__dnd`: `startMatch(seed)`, `sim(seconds)`, `spawnUnit(type, team, x, z)`, `orderMove(units, x, z)`, `orderDig(engineers, flatXZ)`, `terraformDraw('dig'|'fill'|'level', flatXZ)`, `startBuild/placeBuilt/queueUnit`, `deployCMV`, `AI.nextWave = 99999` to stop attack waves, `TS[0].credits` to cheat. Soldiers are instanced (`PARTS`), so `drawUnits` must flag `instanceMatrix.needsUpdate` every frame or infantry go invisible. Structures are modelled at the old small size and scaled up by `BS`/`BSY` inside `makeBldgMesh`. Idle armed units guard their spot (`u.guard`, chase within `LEASH`, then walk back), `callHelp` turns idle friends within 30 m on whoever shot a unit or building, and `baseDefense` sends idle units at enemies near either base. Difficulty `DIFF[diff]` sets first wave, wave gap/size and the computer's damage multiplier. Camera: `cam.tpitch` (clamped `PITCH_MIN`..`PITCH_MAX`) eases into `cam.pitch`; Alt + mouse move tilts and turns, Alt + wheel and PageUp/PageDown tilt, two-finger vertical drag tilts and a two-finger twist turns on touch, V or the View button cycles `VIEWS` presets. Zoom runs `ZOOM_MIN`..`ZOOM_MAX`, fog pushes out with distance and low pitch, and the camera is kept 2.5 m above the ground under it.
- Chew Bubblegum (`chewbubblegum/`): canvas 2D, not three.js, logical 1280 x 720 letterboxed. Scenes `title` → `office` → `cut` → `alloc` in `scenes`, switched with `go()`. Office settled paper, shells and shards are baked into one world-sized canvas (`BKC`) so thousands of sheets cost nothing; floor piles grow via `O.pile`. Allocation answer key is `BUCKETS`; slip states fly/held/rocket/in/bounce/stamped/flyoff. `window.__gum`: `paused`, `sim(seconds)`, `frame()`, `officeShoot(wx, wy)`, `click(x, y)`, `A.auto = true` bot (perfect bot scores ~74, Jeff rank needs 42 and 85%).
- Bedrock Claim (`bedrock-claim/`, isometric gold mining; imported from a claude.ai artifact, so it has its own look: Rye / Barlow Condensed, not the Road Crew style). **Desktop-only exception to the r128 / single-file / phone rules, at JJ's request:** it runs on three.js r187 as ES modules vendored in `bedrock-claim/vendor/` (import map in the page: `three` and `three/addons/`), so it needs a web server (GitHub Pages is fine, `file://` is not) and it no longer publishes as a claude.ai artifact. Graphics: `GFX` is `high` by default (PCF sun shadows from a box that follows the camera in `placeSun`, GTAO + `OutputPass` through `EffectComposer` on a 4x MSAA half-float target, `NeutralToneMapping`, a baked gradient sky for `scene.environment`, `MeshStandardMaterial` everywhere, a tiling noise albedo + normal map on the terrain from `groundTextures`); `?gfx=low` or the Graphics button turns all of that off. r187 lights are physical (no hidden x pi) and colours are managed: hex colours are sRGB, terrain vertex colours go through `s2l()`, canvas colour textures need `colorSpace = SRGBColorSpace`. `PCFSoftShadowMap` is gone in r187 (use `PCFShadowMap` + `shadow.radius`). The terrain casts shadows with `shadowSide = FrontSide`. The dirt grid is 641 x 641 cells of 0.625 m (`?grid=321` gives the old 1.25 m). Testing: serve `.js` as `application/javascript` or the modules will not load; software Chromium takes over a minute per frame-set at full quality, so use `?gfx=low` for logic tests (add `&grid=321` for speed) and full quality only for a screenshot with long timeouts. `__claim.step(dt)` steps the whole sim headless (give the excavator an `order` like `useTool` does and run 20 minutes: about 190 to 200 g in the safe means the crew loop still works). 8 claims in a ring around a mesa town (`TOWN`, `worldOf(slot, u, v)`), height grid `H` over bedrock `BEDR` with `loose`/`looseKind`, `digAt(x, z, r, want)` returns `{vol, gold, payVol}` and `deposit(x, z, vol, kind)` puts dirt back (conserved). Gold is tracked in `Pile` objects and the `ledger`, not in the terrain, so dirt moved by hand carries no gold. Hero `jim` walks or drives `machines` (excavator, loader, dozer, `suv` = Crew 4x4); gold is heavy concentrate (`jim.carry` in lb, `weightFactor`) and only sells in town (`sellGold`, `inTown`). Combat is melee only and everyone shares one move set (`ATK`, `FIGHT`): `light` side swing (wide arc, quick) and `heavy` overhead chop (narrow, slow, staggers), each wind-up -> strike -> recovery with the direction locked at the start (`startAttack(e, kind, yaw, slow)`, `tickFight(e, dt)` does the timing and the hit test, `applyHit` does damage, knockback `kx/kz`, stagger `stag`, block and parry). Fighters are any object passed through `newFight()` (Jimbo, bandits, convoy guards). Stamina `stam` pays for swings, rolls and blocked hits; below half a swing's cost you cannot swing. Block (`e.block`, front 130 degrees) cuts damage to a quarter and costs stamina; a block younger than `FIGHT.parry` seconds is a parry that staggers the attacker. `startRoll` is a tumble with `inv` seconds of invulnerability. Jimbo: left click or Space swings (hold through the wind-up to turn it into a heavy), right click or C blocks, R rolls, G or Q satchel; with no hostile within 14 m the same button is `dig` (a scoop in front, thrown to the right, `digScoop`). A solid hit that involves Jimbo sets `hitStop` (the frame loop passes dt 0 to the sim while it runs) and `shake`. Enemies run `foeBrain`: only the holder of `jimToken` presses the attack on Jimbo, the others circle at about 14 ft; their wind-ups are `FIGHT.aiSlow` times longer and they hit for `FIGHT.aiDmg`; `e.hold = true` pins one in place for tests. The rig from `makeJimbo` is posed by `poseFighter` (waist twist and lean, arm and shovel angles, roll tumble). `fightBars` draws health and stamina over heads and the gold-ready note on the wash plant. Bandits are `foes` (`spawnBandits`), guards live in `outfitTick`. Satchel (`blast`) and berm are still there. Multiplayer uses the claude.ai artifact room (`mp.room`), so it only works when the file is published as an artifact, not on GitHub Pages; hits go over the wire in `myShots`.
