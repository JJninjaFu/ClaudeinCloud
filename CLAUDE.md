# ClaudeinCloud notes for Claude

- JJ's playground for browser games. Each game lives in its own folder as a single `index.html` (no build step).
- Games use three.js **r128** loaded from `https://cdnjs.cloudflare.com/ajax/libs/three.js/r128/three.min.js` so they also publish as claude.ai artifacts (the artifact CSP only allows cdnjs, jsdelivr, unpkg; fonts only from Google Fonts).
- Game HTML files are written as artifact bodies: they start with `<title>` and `<style>`, not `<!doctype>`/`<html>`. Keep `[hidden]{display:none!important}` in each file's own CSS.
- JJ plays on his phone a lot: every game needs touch controls (virtual sticks + big buttons) as well as keyboard and gamepad.
- Style family (shared with Road Crew): safety yellow `#f5b800`, survey orange `#ff6b1a`, dark asphalt panels, Big Shoulders Display / IBM Plex Sans Condensed / IBM Plex Mono.
- Show player-facing measurements in feet and inches (US).
- Testing: headless Chromium via Playwright with `--use-gl=swiftshader`. `window.__pool` (Pool Dig) and `window.__crane` (Topping Out) expose state and a `step(dt, input)` hook for scripted tests. When teleporting the crane in a test, zero `cr.prevV` and `cr.aT` or the load will swing wildly.
- Skyscraper Sim is the long-term plan (demo → dig → pour → steel on one lot); see README. Build each phase as its own playable game first.
- Never put one big ground plane under a dig grid: anything dug below it gets hidden. Build the surroundings as a ring of planes outside the grid (fixed in Pool Dig and Dig & Pour).
- Game files start with charset + viewport `<meta>` tags before `<title>` so they scale right on phones when served from GitHub Pages (harmless as artifact bodies). Root `index.html` is the Pages game menu (a full HTML doc); add new games to it.
- Mineral Fork (dirt bike hillclimb): `window.__game` exposes state; `__game.sim(seconds)` runs the autopilot headless (`autoFeather` true = smooth throttle, which should top out both days; false = pinned, which should fail on the scree).
- Mineral Fork multiplayer: PeerJS rooms (`mineralfork-v1-` + 4-char code), host relays 15 Hz snapshots, 4 riders max, no rider collisions. `__game.mp` exposes the state. To test without the internet, inject a BroadcastChannel stand-in for `window.Peer` before load and open several pages; software-rendered Chromium runs ~1 fps, so drive riders with `__game.sim()` and `bring_to_front()` the page you need frames from.
- Topping Out has three modes: gantry (default), tower (swinging load), hand (drag-to-place). `window.__dig` exposes Dig & Pour state (`startRebar()` skips to the pour).
- Funnin' N Gunnin' (`funnin-n-gunnin/`, RWR-style war): 160 x 120 m map, 1 m terrain grid (`H` vs original `H0`, craters/digging capped at `MAXDIG` below original), building walls are 1 m blocks on 2 levels (`blkIdx`, a wall falls if the block under it dies), bots path with BFS flow fields per point (`rebuildFlow`). 50 soldier slots (0-24 red, 25-49 blue); a human takes over a bot slot. `window.__war` exposes state; `__war.sim(seconds)` runs it headless, `__war.frame()` renders one frame. Multiplayer: PeerJS rooms (`funnin-v1-` + code), host runs all bots, clients own their soldier's position and send triggers; world changes are ops (`cr` crater, `dg` dig, `bd` blocks, `tf` tree) kept in `G.history` so mid-match joiners replay them. Same BroadcastChannel Peer stand-in test works (serve over http, not file://, so the channel is shared).
- Survivin' Skydivin' (`survivin-skydivin/`): solo jump. Plane flies the jump run into the wind over an ideal spot; canopy flight runs at up to 2x time (`timeScale()`), back to 1x below 160 ft. Malfunctions: `twist`, `streamer`, `pcintow`, `lineover` (canopy collisions also wrap you). `window.__sky` exposes state; `__sky.forceMalf = 'streamer'` forces the next opening, `__sky.fast = true` skips the results delay, `__sky.sim(seconds, {idle})` runs the autopilot headless (it flies the whole jump and should land standing up), `__sky.frame()` renders one frame.
- Skydivin' 2 (`skydivin2/`): 4-way formation skydiving. Its world (DZ, trees, hangar, power line, jumper/canopy models) is a copy of the Survivin' Skydivin' world block, so fix bugs in both. Formations are slot lists in `FORMS` ([right, forward, facing] in the formation frame). Host runs bots and the formation (center = average of jumpers, hold 3 s). Freefall positions go over the network relative to a deterministic reference body (`buildRef`/`refAt`) so latency doesn't wreck levels at 120 mph; switch to absolute after break off. PeerJS rooms `skydivin2-v1-` + code, 15 Hz. `window.__sky2.solo(seed)` starts a bot jump, `__sky2.auto = true` lets a bot fly your jumper, `__sky2.sim(seconds)`. The BroadcastChannel Peer stand-in test works (step every page in small 0.1 s chunks with short sleeps so messages flow).
- Test environment note: cdnjs may be blocked from the sandbox. Grab three.js r128 with `git clone --depth 1 --branch r128 --filter=blob:none --sparse https://github.com/mrdoob/three.js` + `git sparse-checkout set --no-cone /build/three.min.js`, then Playwright `page.route('**/three.min.js', ...)` to serve it.
- Funnin' N Gunnin' vehicles (v2): `vehicles[]` (per side jeep, APC, tank, jeep at `v.spot` by HQ), `VT` holds stats/seats (seat 0 driver, 1 gunner, rest riders; `sealed` = APC/tank hide and protect the crew). A soldier in a vehicle has `s.veh`/`s.seat` and is skipped by the foot AI. `vehStep(v, ctl, dt, auth)` drives (only `auth` crushes trees/sandbags/walls and runs people over), `botDrive` follows vehicle flow fields `vflow` (walls inflated by 2 cells), `botGunner` aims the turret, `crewUpdate` fills seats. Net: client drives its own vehicle and sends `V`/`TY`; snapshots carry `V` (vehicle states) and seat codes in soldier slot 10. `__war.vehicles`, `__war.respawnVehicle`, `__war.enterVehicle` help tests. Build parts live outside the repo; edit `funnin-n-gunnin/index.html` directly if they're gone.
